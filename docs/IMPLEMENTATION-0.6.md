# R6 Camera 0.6：水平儀置中、連拍試速與鳥眼驗收工具

本輪使用者批准：鳥眼離線模型須權利、100 張獨立真實圖及 iPhone 效能均通過；水平儀以 4:3 影像中心為固定基準；保留所選照片畫質提高連拍速度。從 `2f58969efee05cda2a456fe1aa8fea3f1f7a77b9` 繼續，原始工作目錄乾淨。

## 實作

- 水平儀明確定位在 `ViewfinderGeometry.imageRect` 的中心；大／小尺寸相同基準，俯仰線仍可移動。UI 測試分別斷言與取景框中心相差不超過 1 點。
- 驅動模式新增 H+ 請求上限 8／測試10／測試12；後兩者 H 請求上限為6，標準H為4、L為1。預設8，不自動提高未驗證的裝置上限。標準上限只在 responsive、約24MP以下（≤2500萬像素）、非RAW及非精確曝光條件允許；高解析度預設仍4／2。明確選擇測試10／12時，可在支援responsive的高解析度HEIF／JPEG下試速，尺寸及品質策略完全不改；RAW／精確手動曝光／不支援responsive仍保守限制。這些是試速請求上限，沒有真機吞吐保證。
- 改為連續三次受阻／遲到才逐級降低排程速度，連續12次穩定接納才逐級恢復；不超過選定上限／曝光下限、不補拍、不增加緩衝容量。
- 最近一次連拍量測可於 MENU→設定分享 JSON：每張請求、實際快門回呼、系統處理完成、App render開始及儲存完成的單調時間、實際照片尺寸、受阻原因、P95間隔偏差。量測只涵蓋 App 存檔，不含系統相簿匯出；最多256張，截斷不判定10秒驗收通過。這是一段量測，不是自動認證某機型／格式。
- 鳥眼 adapter 統一遵守 `BirdPosePredicting`，保留真實眼／頭點；過期（250ms）與逆序推論不可更新鎖框或鏡頭。推論節流改為80ms且仍只有一個在途推論，這是排程上限，不代表手機達成10Hz。
- 新增獨立鳥眼評分工具、遮眼／多候選等公式測試，強化模型發布證據檢查；研究詳見 [鳥眼0.6證據](research/bird-eye-0.6.md)。

## 驗收與交付狀態

本機 Windows 無 Xcode／Swift 工具鏈；本機可跑 Python、Swift 語法樹檢查、IPA結構檢查。Swift型別檢查、核心／iOS／UI測試、實際截圖與archive透過GitHub的Xcode27執行，結果以該run為準。

**鳥眼未完成：**沒有合格的可打包權重，也沒有100張獨立真實圖或連接的iPhone。目前IPA必須明確標示無鳥眼模型，不把評分工具或合成測試宣稱成鳥眼功能。synthet來源條件仍未釐清；I-MuPPET不是合格即時替代品。

**真機待測：**H+8／10／12、H4／6、RAW／高解析度／長曝光／慢存檔各連續10秒，95%間隔偏差≤20%才可列為該配置通過；沒有結果時不承諾實際幀率。按鍵、近遠景合焦、水平儀感測方向／連續使用、鳥眼定位及效能也未驗收。音量鍵可能觸發快門的既有缺口保留。

畫質、解析度、格式不因試速改動，不用影片影格替代照片。觸控前基本AF、白框不驅動指定對焦點；指定主體唯一藍框、空白點單次對焦、遺失不跳鎖；四邊拍攝回饋與既有轉盤方向維持。
