# R6 Camera revision — approved 2026-10-22

Source: user conversation, scheduled execution at 01:10 Asia/Taipei, and the subsequent approved 0.3 correction plan. The following focus and feedback rules supersede 0.2 behavior.

- Fixed landscape with Camera Control on the upper right; Dynamic Island left, USB-C right. UIInterfaceOrientationLandscapeRight. All pages stay landscape.
- Before touch, use system continuous scene AF and draw at most one WHITE candidate box. Candidate coordinates never drive AF. Touch an identified subject: one BLUE box and continuous subject lens AF, eye → observed head → body. Touch elsewhere: fixed BLUE square and exactly one single AF operation, then keep focus. New detections must not activate tracking from point mode. Unlock or lost target returns to scene AF with white candidate preview. Short occlusion preserves locked target/distance for 0.8s; no jump to bystanders. MF stays manual.
- Camera Control is shutter only, full down captures once; burst down starts/up stops. No half-press or hardware slide controls. No extra on-screen giant shutter.
- Camera-Control-only capture is required: volume buttons must not capture. The existing shared public event API does not establish a source filter; inspect actual iOS27 SDK headers and report this as blocked if no supported path exists. Do not invent event.source or silently call primary-only handling a solution. See research/camera-control-only.md. The user explicitly accepted retaining the shared hardware handler temporarily (including volume-button capture); no extra on-screen shutter is added.
- Never overlay the captured image over live view. On a successful capture callback, show only a thin white viewfinder border for 120ms then fade over 80ms; independent of file writes/style rendering. Remove photo-review seconds from menus; retain gallery access and legacy preset decoding.
- Main HUD/secondary controls follow manual, not invented image glyphs. White balance/style/meter/subject on right; mode/AF/quality/drive on left. No fictitious card, accessory or resolution capabilities. Secondary menus must use their documented editor family; see research/canon-ui-reference.md.
- Visual references: design/approved-zoom.png (approved partial circular right wheel), design/candidate-hud.png (latest candidate-state sketch), design/screen-map.png (Q/MENU/playback). Use deterministic vector drawing, not generated raster icons.
- Zoom drag: downward increases zoom, upward decreases it. Keep lower zoom labels above the pointer and higher labels below; do not reverse the approved circle geometry or tick layout.
- Preserve P/Tv/M/Fv/A+, actual fixed aperture, supported formats, styles, WB, MF/peaking/magnification, grid/histogram, presets, timer/burst, local-first saves and gallery. Settings retain compatibility. Single AF is a touch-point action rather than a permanent AF-operation choice.
