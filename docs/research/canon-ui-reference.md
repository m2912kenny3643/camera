## Verified overall structure

- **Main still-photo display, pp. 1051–1053:** live image dominates. Left rail descends through mode, AF area, AF operation, card/quality, drive, aspect/crop. Right rail descends through Q, anti-flicker, WB, Picture Style, metering, subject detection, display simulation and magnification. Bottom strip is shutter / aperture / exposure scale / ISO. Only current applicable settings appear; do not invent active statuses for unsupported hardware.
- **Default still Q, pp. 99–100 and 105:** Q does not inherently mean a full-screen 12-card dashboard. It preserves live view, highlights a small rail button with amber outline, gives its name in a translucent band near the bottom, and displays the selected setting's small option glyphs in a bottom strip. Back is a hooked-left arrow in a rectangular dark button at the upper right. INFO is a boxed label followed by the context-specific action.
- **Custom Q, p. 100:** a separate black compact dashboard is documented. P is upper left, ISO AUTO upper right; exposure scale uses a wide rectangular cell; smaller icon/value cells are unequal sizes. Bottom row is a gray help strip with a back-arrow cell. This is not an evenly sized grid of large text cards. Item order/layout are customizable (pp. 441–443).
- **pp. 101–104:** these describe movie Q display 1/display 2. Their large tile-page workflow is not evidence for the default still-photo layout.
- **MENU, pp. 95–96 and 487:** black background; horizontal top category glyphs; selected category gets colored fill; subordinate page marks below; a small title and page count precede dark-gray rows. Label left, value right. Active row has a colored outer band and black inner inset. Camera category is red, AF is magenta. Do not use one amber theme for every secondary menu.

## Stable rules for this app

1. A main-screen control opens its own secondary editor directly. Do not route every rail control through the same generic Q dashboard.
2. Reuse the verified **AF magenta list/palette**, **shooting red list**, and **live-view amber palette** families. Include contextual title, current option, return action, and SET OK where the screenshot has them.
3. Prefer named white text and hand-drawn geometric glyphs derived from inspected shapes. Do not invent animal mascots, emoji, or unrelated SF Symbols as supposedly authentic Canon icons.
4. Treat option choice as pending within editors that show SET OK; SET confirms and returns, back cancels pending choice. Live Q's immediate turn-to-adjust behavior may remain immediate; do not impose one confirmation policy on every family.
5. Maintain a separate draft value so returning from an editor does not leave a misleading highlighted value. Preserve capture/program settings outside the edited property.
6. Match real supported semantics before visual abundance: fixed aperture remains fixed, area AF requires backend support, native zoom stays native, unsupported eye species remain body tracking. No false buttons for camera-only functions.
7. Validate both orientations with screenshots: editor controls must fit within safe area; live-view overlays must not silently turn into standard iOS form sheets.

## Evidence boundaries

- Exact category glyph geometry for every subject choice is **not** established by the inspected subject text pages. The main display's subject glyph is visible at callout (24), p. 1051; inspect that image before reproducing it. Do not infer all animal or vehicle icons from it.
- The manual demonstrates configurable Q layouts and different contextual screens; there is no single mandatory universal 12-item layout.
- These references establish Canon UI and ordering, not that AVFoundation can duplicate Canon AF, metering, processing or RAW formats.
